# Rote 优化需求与开发准备

日期：2026-10-06  
状态：开发范围已确认，首版代码已实施；本地验证及生产交接边界见 `PRODUCT-OPTIMIZATION-DELIVERY.zh.md`。

## 1. 目标与范围

本次目标：将数据库迁到 Supabase、完善 Post 图片支持、增加 AI 评论、移除无关推广。

用户已明确：不增加 AI 聊天图片功能。现有 AI 聊天保持当前能力。

用户已确认：“Post”包括短笔记 Rote 和长文章 Article，两者都支持图片。短笔记已有独立附件编辑能力，两种内容的数据关系分别处理。

### 首版建议（尚非用户确认的产品决策）

- Supabase 仅承载 PostgreSQL；保留现有 Hono 后端、Drizzle、账号认证和对象存储。
- 长文章沿用 Markdown 正文内图片，不新建图库编辑器。
- AI 评论按两种 Post 类型规划，作者手动触发、仅作者可见、文本点评。
- 保留现有聊天历史存储方式；不增加聊天同步或多模态聊天。
- 去推广按明确入口清单处理，不删除许可证、版权说明或必要文档。

## 2. 当前实现与差距

以下结论来自当前代码，不代表线上运行验证。

| 模块 | 当前证据 | 差距或风险 |
| --- | --- | --- |
| 数据库 | `server/utils/drizzle.ts` 使用 postgres.js + Drizzle，环境变量为 `POSTGRESQL_URL` | 需要验证托管数据库连接、权限、扩展、迁移及后台任务 |
| 数据结构 | `server/drizzle/schema.ts`、`server/drizzle/oauthMcpSchema.ts` | 必须保留业务表及 OAuth/MCP 数据，不能只迁笔记 |
| 后台锁 | `withDatabaseAdvisoryLock` 使用会话级 advisory lock；推送等模块调用 | Transaction pooler 不能直接视为现有连接的等价替换 |
| Article 图片输入 | `web/src/pages/article/edit.tsx` 已支持粘贴、拖入图片并插入 Markdown URL | 缺少显式选图入口；上传期间保存、失败占位、草稿恢复需要验证和完善 |
| Rote 图片输入 | `web/src/components/editor/RoteEditor.tsx` 已支持图片附件、粘贴/拖入及九图限制，`NoteSubmission` 负责提交 | 核对选图、排序、删除、提交和阅读体验，复用现有机制 |
| 图片归属 | `attachments` 有 `userid`、`roteid`，没有 Article 关系；文章正文存 URL | 上传文件与文章缺少明确的持久引用关系 |
| 未绑定图片清理 | `server/attachments/unboundCleanup.ts` 以无 `roteid`、超过 7 天、非头像/封面为候选 | 未排除正文图片；默认 observe，启用 enforce 时可能误删文章图片 |
| AI 评论 | 未发现完整评论表及评论功能 | 新增领域模块、数据结构、接口和 UI |
| 推广入口 | 首页快捷链接、GitHub 数据、探索页社区项目/App/演示站 | 具体删除清单待确认；不能把所有外链都视为广告 |

## 3. Supabase 数据库迁移

### DB-01 连接与运行配置

- 应用仍通过后端连接数据库；不要求前端改为 Supabase SDK。
- 按部署网络选择直连或 Session pooler，验证 SSL、连接数量和超时。
- 迁移命令与运行连接分别评估；必要时新增迁移专用连接配置。
- 检查服务端、推送 worker 和其他任务的总连接数。
- 保留现有会话锁语义，验证并发调度与锁释放。若未来使用 Transaction pooler，必须另行设计和验证锁及驱动行为。

### DB-02 数据与扩展

- 新部署：在隔离 Supabase 项目完整执行 Drizzle 迁移。
- 已有数据：先备份并演练恢复，再迁移业务 schema、数据、索引、触发器、迁移记录。
- 不覆盖 Supabase 管理的 auth/storage 等 schema。
- 验证 UUID 默认值、数组、JSONB、外键和业务触发器。
- 验证 pgcrypto、pgvector 的权限、schema/search_path、向量索引及检索结果。
- 尽量保留兼容的现有向量；若必须重建，报告原因、费用和检索恢复条件。

### DB-03 权限与部署

- 保留现有后端鉴权和内容访问规则。
- 明确 Data API 是否启用及暴露的 schema；不使用时关闭或限制暴露范围，不能假设现有 JWT 自动满足 Supabase RLS。
- 数据库密码、AI 密钥及高权限服务凭据仅保存在服务端。
- 调整 Compose 的数据库环境变量、容器依赖和启动等待逻辑，保留本地开发数据库选项。
- 更新环境变量示例、自部署说明和部署检查步骤。

### DB-04 生产切换

- 明确目标项目、区域、已有数据量、是否接受维护窗口。
- 提供备份、迁移、数据核对、切换和回退步骤。
- 核对所有业务表行数、关键记录/关联、私有内容权限、附件引用及 AI 配置。
- 生产写入切换后回退必须处理新增数据；不能直接切回旧库造成数据丢失。
- 本阶段不执行生产迁移，待配置和切换方案具备后再安排。

验收：登录、CRUD、文章引用、附件确认、检索、OAuth/MCP 和推送等现有能力通过适用检查；会话锁在目标连接方式下有效；旧数据与迁移记录核对通过；备份恢复演练成功。

## 4. Post 图片支持（Rote 与 Article）

### IMG-00 短笔记 Rote

- 保留附件图片区，沿用当前最多九张图片及现有图片/视频互斥规则，不无依据地改动限制。
- 核对显式选图、粘贴、拖入、预览、排序及删除；补齐确实缺失的交互。
- 复用 `RoteEditor`、`AttachmentList`、`AttachmentItem` 和 `NoteSubmission`，不复制一套上传实现。
- 新建/编辑提交后保持附件与笔记归属、顺序和资源账本一致。
- 列表、详情、公开分享及移动端均能正常阅读、点击放大。
- 验收覆盖九图边界、只发图片、编辑移除图片、上传失败及越权引用；已有直传回归测试必须继续通过。

以下 IMG-01 至 IMG-03 主要针对长文章 Article；IMG-04 对两种 Post 都适用。

### IMG-01 编辑与提交

- 增加可发现的选图按钮，保留粘贴、拖入和 Markdown 编辑。
- 按光标位置插图，多图保持用户选择顺序。
- 简单显示上传状态；有进行中的上传时禁止提交，不能持久化临时 UUID 占位。
- 失败时提供本地化错误信息，并允许用户重新选图；不引入专用恢复面板。
- 上传结果、用户输入与草稿缓存保持一致，刷新后不恢复过期上传占位。
- 正文删除图片引用应保存成功；外链图片继续按正文内容处理。
- 移动端能选图和正常提交。

### IMG-02 持久引用与生命周期

- 建议新增 Article—Attachment 关系表，同一图片可被多篇文章引用；最终 schema 在实现前核对资源账本语义。
- 创建/更新文章时同步正文中本系统附件的引用；同一操作中的内容与关系更新应保持事务一致性。
- 只绑定当前作者拥有的附件；不能把其他用户的附件 ID 或 URL 变为自己的资源。
- 外部 URL 不自动登记为本系统附件，不发起后台抓取。
- 已被 Article 引用的附件不进入未绑定清理候选；并发保存与清理也必须保持该规则。
- 删除文章或移除引用只释放相应关系；仍被其他文章、笔记、头像等使用的对象不得删除。
- 旧文章按作者与正文 URL 匹配进行数据引用回填，覆盖原图/压缩图 URL；无法匹配的项输出报告，不误删。
- 将回填作为清理启用前置条件，不通过默认关闭清理来掩盖引用缺口。
- 关系回填和引用核对只做数据库工作，不增加对象 HEAD/GET/COPY 或媒体处理。

### IMG-03 阅读与分享

- 编辑预览、详情页和公开笔记引用入口均正常显示正文图片。
- 图片适应窄屏，不横向撑破正文；提供可访问的点击放大入口。
- 文章访问规则沿用现有作者/公开笔记引用逻辑。
- 当前对象 URL 的实际访问范围需要核对：页面私有不等于图片 URL 私有。如需私有图片存储，应作为明确的访问策略变更单独评估。
- 首版不强制增加封面、图库排序或图片生成。

### IMG-04 上传政策边界

严格遵守 AGENTS.md：信任客户端声明的附件元数据，浏览器直传最终对象 key，确认阶段仅做数据库工作。保留身份、对象/内容归属、基础输入和幂等校验；不恢复物理内容/大小验证、验证 worker 或复杂提交失败流程。

验收：选图/粘贴/拖入、多图顺序、上传中提交、失败后编辑、刷新草稿、保存后重开、移动端阅读、文章删除及共享引用均通过。模拟超过清理保留期，文章引用的图片仍保留；移除最后引用后的清理符合资源账本规则。旧文章回填后仍可读。

## 5. AI 评论

### AI-01 首版行为（建议默认）

- 作者在 Rote 或 Article 的详情页手动点击“AI 点评”；分别点评当前目标正文，不默认把关联文章和笔记混成同一条内容。
- 默认仅作者可见；公开 Post 不自动公开点评。
- 根据当前正文生成简短文本评论，不读取其他用户私有数据。
- 图片理解不纳入首版；仅有图片而无可点评文本时明确提示，不编造图片内容。
- 评论带明确 AI 标识，支持删除、重新生成。
- 内容变化后旧评论显示“基于旧版本”，不把旧点评当作新正文的点评。
- 自动发布点评、公开讨论、人工回复、嵌套评论和消息通知不纳入首版。

### AI-02 数据与接口

- 为 Rote 与 Article 建立有外键约束的评论关系。可采用两种可空外键加恰好一个非空的约束；最终结构在实现时确定，避免无约束的任意 target ID。
- 建议字段：ID、目标 ID、owner ID、正文、模型、来源内容版本/hash、创建时间。
- 生成请求记录幂等键与状态，防止相同请求重复收费或落库。
- 生成前鉴权；落库前再次检查目标存在、归属和版本。生成途中修改正文时提示重新生成，不落入当前版本。
- 复用现有 AI 配置、权限和用量记录，核对用量类型是否需要新增。
- 模型调用失败不产生成功评论；删除/重生成按明确 API 完成。
- 正文和引用内容作为数据处理，不作为模型系统指令。
- 密钥仅服务端使用；首版优先使用站点 AI，个人/本地 AI 评论不默认纳入。

验收：作者生成成功；未登录/非作者无法生成或读取私有点评；重复请求不重复落库；失败状态可理解；正文更新、并发生成、目标删除、删除评论和重新生成均符合上述规则。

## 7. 开发拆分与验证

| 阶段 | 交付物 | 前置条件 |
| --- | --- | --- |
| P0 准备 | 分支基线、现有运行基线、配置清单 | develop 可用；Post 两种类型已确认 |
| P1 图片 | 图片入口、持久引用、旧数据回填、清理保护、展示完善 | 存储访问策略明确；先保护已有图片 |
| P2 Supabase | 连接配置、隔离环境迁移验证、部署/切换手册 | Supabase 测试项目与连接凭据；已有数据情况明确 |
| P3 AI 评论 | 两种 Post 的评论 schema、服务/API、详情 UI、本地化及验证 | 评论触发/可见性规则明确；站点 AI 可用 |
| P4 推广清理 | 已确认入口清单的组件/文案/请求清理 | 删除清单明确，可与前述功能独立开发 |
| P5 发布 | 完整验收、备份恢复演练、生产切换 | 各阶段验收完成及发布授权 |

每个代码阶段完成后：

- 前端改动在 `web/` 运行 `bun run lint`、`bun run build`。
- 后端改动在 `server/` 运行 `bun run lint`、`bun run build`。
- 新增有价值的引用生命周期、权限、幂等、版本并发及迁移集成测试。
- 图片清理测试同时覆盖“应保留”与“应清理”，不能只测保护分支。
- 页面功能需要浏览器实际验收；纯代码检查不能替代视觉或运行验证。
- 提交时必须让项目 Codex hook 运行，不绕过失败的质量门禁。
- 工作分支必须从 develop 创建，PR 目标必须为 develop，推送前核对两者。
